# Plan: brandly-cli Timeline/Editor UI (Remotion-style)

## Context

brandly-cli is a Python CLI for AI video generation. Currently all interaction is terminal-based (Rich console). The user wants a **browser-based visual timeline editor** similar to Remotion Studio — drag-to-reorder clips, trim durations, preview playback, regenerate shots, and export. Dual interface: CLI developer API + browser visual editor.

**Key insight**: brandly-cli generates *real MP4 clips* via AI (Agnes/MiniMax), unlike Remotion which generates video from React code. The timeline editor operates on **existing video files** + metadata, not procedural compositions. HyperFrames (sibling tool) uses HTML+GSAP compositions with a seekable timeline — its `preview --context` agent bridge pattern is the model for programmatic UI control.

---

## Architecture Decision

**Runtime: Embedded FastAPI server + React SPA (Vite)**

- `brandly timeline` (no args) starts a FastAPI server on `127.0.0.1:8765`, lists all `.brandly/` projects in the browser, user picks one
- React SPA built with Vite, **embedded** in the Python package — `npm run build` output copied to `src/brandly_cli/web/static/` at install time or during dev
- REST API for timeline CRUD; **WebSocket** for generation progress events
- **No Electron** — browser-based, lighter, matches HyperFrames Studio pattern
- **No HyperFrames integration** — brandly clips are real MP4s, not HTML compositions

**Why not alternatives:**
- Node.js-only frontend: adds second runtime to maintain
- Server-rendered HTML: no interactive timeline possible
- Remotion Studio clone: overkill, Remotion's React-composition model doesn't match AI-generated clips

## Data Model

### Canonical: `timeline.json` (new file per project)

```python
# src/brandly_cli/web/models.py
class Clip(BaseModel):
    id: str                          # e.g. "shot-1"
    clip_path: str                   # relative: "videos/scenes/Scene-01-Shot-1.mp4"
    prompt: str
    duration: float                  # seconds (user-editable)
    actual_duration: float | None    # from ffprobe on load
    style: str = "cinematic"
    transition_in: str | None = None # "fade" | "dissolve" | "wipe" | "slide"
    transition_duration: float = 0.5
    volume: float = 1.0
    status: str = "pending"          # "pending" | "completed" | "generating" | "failed"

class ProjectTimeline(BaseModel):
    project_id: str
    clips: list[Clip] = []
    aspect_ratio: str = "16:9"
    fps: int = 24
    color_grade: str = "cinematic"
    created_at: str = ""
    updated_at: str = ""
```

### File sync strategy

| Editor action | Files written |
|---|---|
| Reorder/trim/transition edit | `timeline.json` (authoritative) + `shots.json` (regenerated for `brandly produce` compatibility) |
| Regenerate a shot | `timeline.json` status → `generating` → `completed`; production plan row → PENDING |
| Export/stitch | triggers `stitch.stitch_videos()` → writes to `export/` |

**Never writes to `production_plan.md` directly** — that remains CLI-generated. `timeline.json` is the editor's source of truth.

### Key Interactions

| Gesture | Action | Implementation |
|---|---|---|
| Drag clip body | Reorder | `@dnd-kit` SortableContext |
| Drag left handle | Trim start | Custom pointer drag, constrain ≥1s |
| Drag right handle | Trim end | Custom pointer drag, clamp ≤12s (Agnes max) |
| Click transition zone | Open picker | Popover with 4 transition options |
| Click clip | Select + preview | Loads clip into PreviewPlayer |
| Click play | Sequential playback | Zustand state machine → single `<video>` |
| Double-click clip | Edit prompt | Opens ClipEditor prompt field |

### State Machine for Playback

```ts
type PlayStep =
  | { kind: 'playing'; clipIndex: number }
  | { kind: 'done' }

// on <video onEnded>: advance clipIndex, reset currentTime, continue playing
// on seek: jump to globalTime, find which clip contains that time, set local time
```

### Critical Backend Constraints (visible in UI)

- `AGNES_MAX_SHOT_DURATION = 12` — trim right handle clamps at 12s, shows warning
- Transitions from `stitch.py`: `("fade", "dissolve", "wipe", "slide")` — imported from API, not hardcoded
- Clip filenames are deterministic: `Scene-{scene:02d}-Shot-{scene}-{shot_in_scene}.mp4`

## API Surface

```
GET  /health                              # server alive check
GET  /projects                            # list all .brandly/ projects
GET  /projects/{id}                       # project metadata
GET  /projects/{id}/timeline              # current timeline (ProjectTimeline)
PUT  /projects/{id}/timeline              # full timeline replacement (reorder/duration/transition)
PATCH  /projects/{id}/clips/{clip_id}     # update single clip field
POST /projects/{id}/clips/{clip_id}/regenerate  # re-run AI generation for one shot
POST /projects/{id}/export                # stitch all clips → final MP4
GET  /projects/{id}/clips/{clip_id}/preview   # streaming preview URL (for video element src)
GET  /projects/{id}/clips/{clip_id}/thumb   # first-frame thumbnail PNG
WS   /projects/{id}/ws                    # WebSocket: generation progress events (SSE-style JSON)
```

## Decisions Made

1. **Packaging**: React SPA embedded — `npm run build` → `src/brandly_cli/web/static/`. Single `pip install brandly-cli[web]` gives both server and UI.
2. **Progress updates**: WebSocket (`/projects/{id}/ws`) for real-time generation progress.
3. **Project discovery**: `brandly timeline` (no args) auto-lists all `.brandly/` projects; user picks from browser UI.

---

## Known Risks

1. **ffmpeg dependency**: `brandly timeline` requires ffmpeg for thumbnail extraction and export stitching. Error gracefully if missing.
2. **Build step**: `npm run build` must succeed for the package to work. Consider a fallback static HTML if Node.js is unavailable.
3. **State drift**: If user edits `shots.json` via CLI while the editor is open, the editor should re-fetch on next action (no auto-reload needed).
